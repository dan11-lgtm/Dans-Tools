What this reads
TMR DESIGN-model exports carry no alignment geometry — horizontal and vertical data lives in the CONTROL <area> RDW MAJOR / MINOR / DRAINS models. Export the CONTROL model to .12da and load it here. UTF-16LE with a BOM is handled automatically and .12daz is unzipped in the browser.

Solved geometry is read in preference to the parametric parts. In horizontal_data the vertices are tangent points and radius_data gives the radius of the segment starting at each one, so the chain is read directly as arcs and straights rather than solved from intersection points. Start chainage is taken from the block, so a line beginning at ch 45099 stays in absolute chainage and the profile lines up. In vertical_data the vertices are tangent points and the parallel geometry_data array marks each vertical curve with its VIP chainage and height, from which the length follows. Radius sign gives the hand: positive right, negative left.

drawables and additional_geometry are skipped — they hold label and offset-string geometry that otherwise reads as an alignment. Closed strings are recognised as circulating carriageway. The design block is read for design speed, template, crossfall and lane counts, so those are not retyped. Where a solved export is not available the parametric parts are parsed instead, and solver-determined or computator geometry is reported Not Assessed with the reason — never guessed.

LONG SECTION. The profile over chainage, with the plan geometry, operating speed and every located finding drawn underneath at the chainage it applies to. Rules are grouped by family, so the shape of the problem is visible before a single row is read — a column of red across several families at one chainage is one defect, not six. Click any bar to see the finding and why it failed. Scroll to zoom, drag to pan.
Shaded bands on the profile are vertical curves, blue for crests and violet for sags, with K and length where there is room. The plan band shows arcs in orange for right-hand and blue for left-hand with the radius, straights as a line. Levels are drawn to a fitted range, so the vertical scale is exaggerated against the horizontal — grades are labelled numerically rather than read off the slope.
MODEL VIEW. The alignment built from the horizontal chain and lifted onto the vertical profile. Ribbon colour is the worst verdict against that element, so a red length of road is a length with a failing check on it. Double-click any row in the ledger or report to fly here and highlight it; double-click a marker here to select it. Drag to orbit, shift-drag or right-drag to pan, wheel to zoom.

Geometry is reconstructed from IP coordinates, tangent lengths and arc centres, then stationed at and lifted onto the parabolic vertical curves. Spirals are drawn as their circular arc, so transition lengths are assessed numerically by rules HZ-07 and HZ-08 rather than shown here. The ribbon uses the carriageway width from the corridor model () and does not represent medians or earthworks. The batter overlay is an indicative catchline at the slope set on the corridor tab, drawn against the model datum — it is a sense check on reserve width, not a surface. An element reads grey where a check on it could not be assessed — most often because a sight-line clearance or an availability figure has not been entered on the corridor tab. Grey is not a pass, and it is not “nothing was checked”; rows that merely report a derived value never colour an element grey.

Sight-line envelope §5.4 · §5.4.2 · §5.6.4
Measures available sight distance on the running surface at the inside lane centre, station by station, rather than from a plan-view offset. Because the eye and object sit on the surface rather than the centreline, the §5.4.2 crossfall effect falls out of the model — adverse crossfall on a crest reduces available sight distance and superelevation increases it. This also measures overtaking provision as a real percentage of length for the Table 9.1 warrant.

THE SUPPLEMENTS HAVE PRECEDENCE. TMR states that when applied in Queensland the RPDM supplements take precedence over the corresponding part of the Austroads Guide. Where a section does not appear in a supplement, the Austroads criteria is accepted unamended. The Part 3 supplement is written against AGRD Part 3 (2021) — Edition 3.4, not Edition 4.0 — so rule QL-00 reports that adoption gap on every audit.

WHERE THESE VALUES COME FROM. The tables below are the published values of the selected edition, entered as data and read by the rule engine — they are not editable, because editing a published table would break the audit trail. What is configurable is the design domain: which reaction time, deceleration coefficient, terrain, drainage condition and sag criterion apply to this project. Standard text is never reproduced; logic is referenced by table and clause number. The active row for the current design domain is highlighted. TMR RPDM Volume 3 Part 3 supplements and in places overrides Austroads for Queensland work — confirm which edition TMR has adopted before relying on this output.

PROJECT. Everything needed to reproduce an audit lives in one project file: the alignments, the parameters, the saved revisions and the audit-all register. The file records the standards pack it was saved against, so reopening it under a newer pack says so. The session also autosaves in this browser.
Project details
Audit all alignments
Each control line is audited from the same starting parameters, so one string's design block cannot carry into the next. The workbook holds the basis, the register, every finding and the precedence table.
SELF-TEST. Runs the engine's regression suite in a separate instance, so the project is not touched. The table values are compared cell by cell with an independently entered reference set, the closed forms are checked against the tables, the verdict logic is swept for direction, the parsers are round-tripped on built-in fixtures, every defect fixed in v5.0 is pinned, and a recorded audit is re-run to catch any change in behaviour. The same suite runs headless at build time. Run it after opening the tool on a new machine and before relying on a report.
